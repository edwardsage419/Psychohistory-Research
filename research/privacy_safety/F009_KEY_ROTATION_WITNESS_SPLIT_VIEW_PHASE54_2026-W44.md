## Original English standards and design sources
RFC 9162 (December 2021, Experimental), https://www.rfc-editor.org/rfc/rfc9162.html , Section 11.3 explicitly describes inconsistent log views and gossip of signed tree heads. Sigstore Rekor architecture, https://github.com/sigstore/architecture-docs/blob/main/rekor-spec.md , Section 10.2 describes multiple independent witnesses, checkpoint persistence and distributors. These standards target certificate and software transparency, respectively. Applying them to personal decision credential recovery is a candidate analogy, not an existing requirement or deployed security guarantee.

## Synthetic witness experiment

Enumerated all 3^3=27 ordered combinations in a standalone JavaScript program archived at research/privacy_safety/f009_phase54_witness_split_view_20261101.js. Candidate rule: if two distinct roots are visible for the same issuer/epoch, CONFLICT_QUARANTINE; otherwise at least two matching witness responses permit REVIEW_ONLY; otherwise UNKNOWN_QUARANTINE. A,A,B is quarantined despite majority A; A,A,MISSING enters human review; A,MISSING,MISSING is unknown. No state permits automatic high-impact recovery. These counts enumerate constructed messages, not attack frequencies.

## Key rotation, authorization, privacy, and limitations
Before accepting a witness response, future candidate controls must separately authenticate the issuer identity, signing key lineage, epoch, checkpoint size/root, and independent witness identity; compare stable checkpoints and consistency proofs; preserve trusted monotonic version and freshness. Revoked/compromised keys and conflicting key rotations require external current-authority evidence. Multiple witnesses with shared operator, keys, device or network are correlated; two identical responses do not guarantee global consistency or honest quorum. Checkpoint requests containing account IDs or stable credential indexes may create cross-service linkage, so prefer locally cached public checkpoints with minimal identifying queries and a documented deletion schedule. Preserve user appeal and UNKNOWN, never override human authorization or set universal utility weights.
