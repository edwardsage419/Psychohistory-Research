## Mechanism
Inputs: local note changes, before_change_item, item_changes ID, settings and encrypted status. State: local revision diffs, lastProcessedChangeId cursor, sync/decryption source exclusions, revision TTL. Algorithm: collectRevisions queries changes after cursor, saves revisions for eligible notes; a generic diff creation error is logged and processing continues, then lastProcessedChangeId advances even for the failed change. Comment in pinned code explicitly says the skipped change will never be processed again. The special revision_encrypted error instead stops processing before cursor advancement. Disabled service advances the cursor to last change ID while cleaning old revisions. Revision.ts merges surviving diffs before deletion and defers deletion on encrypted revision errors.
