# v0.2 合成比较工作区

使用仓库根目录下的当前检出。首次安装可使用原有 `scripts/install.sh`，随后从平台目录运行 `bash scripts/run.sh serve`。本地授权令牌的用法与 v0.1 相同。

1. 打开“研究工作流”，登记 R123、R132 或 R233，核对提交、blob 和 SHA256。R123 提供 DeGroot 理论来源，R132 和 R233 提供结构不同的审计记录。
2. 选用经过校验的 main R123 记录和 `r123-degroot@1.0.0`，创建协议草稿并查阅其版本、目标、数据划分、截止、指标和计算预算。候选提交从本地 Git 对象浏览，执行许可始终为浏览。
3. 批准协议，提交实验，再单独批准该次执行。取消和失败会保留原记录。执行前取消或被阻塞的任务可沿用原协议重试，并引用先前记录。worker 启动前持久登记留出集使用，即使启动或保存失败也须用新种子继续。已完成留出集返回原结果。协议包含源码哈希，源码版本变化后需使用原版本或新种子。
4. 查看 Brier、Log Loss、训练基线、各合成研究表现、固定权重敏感性和真实世界证据 UNKNOWN。历史结果按运行 ID 与内容哈希读取。

CLI 使用相同的授权、调度和评分函数。从平台目录运行 `bash scripts/run.sh research --help` 查看入口。完整流程用 `scripts/verify_v02_cli.py` 记录实际命令与退出码。Web 和 CLI 同时操作时，CLI 的只读命令可和 Web 共用数据根，执行管理命令由持有调度锁的进程处理。

## 数据兼容与回滚

v0.2 在 schema 2 中追加两个研究记录表和索引。已有运行 JSON、对象内容、SQLite 备份与 v1 端点语义继续沿用。v2 对比记录使用独立的 `kind`，v1 列表继续只返回原实验。当前源码无法按旧源码身份重新计算未执行的 v0.1 任务，这些任务会留下 BLOCKED 记录。

升级前在活动任务结束后用旧版 CLI 备份。回滚时检出原版本，将升级前备份恢复到新根并将旧版服务指向它。保留升级后的根和备份以供 v0.2 查看，避免旧版调度器接管 v2 队列。旧版实验的冻结工件继续按原哈希核验。
