# v0.4 个人决策中枢设计

设计基线为 `5909e1ae58dbfcb0d14d00c0561726ecb35e1028`、项目规程 v3.1、近期交接清单和正式 v0.4 开发任务。代码、报告与合成材料在一条独立分支交付，由所有者审阅。

## 架构与实施选择

复用 Python API、命令行、显式注册表和 React 工作台。采用同进程中的无状态决策协调器，个人记录使用单独的私有 SQLite 数据根。独立服务会增加部署、认证与故障面，当前环回单用户规模无需引入。将调度放进 React 会让 CLI 与界面各有一套计算和审计，因此由后端提供两者共用的接口。

开放原文和澄清结果存于版本化状态。默认澄清提供有针对性的问题，当前任务环境缺少已核实可授权的免费推理服务。预留显式注入、逐次许可的候选建议协议，输出仍须确认。编辑后以新状态重算，原文、数据来源、适用规则和输入摘要随已保存的版本追溯。

模型先过 C028 硬约束，再依真实输入验证卡片上的适用条件。注册表复用固定模型身份、显式添加和描述契约。新卡片返回统一的表、图区间和结论元数据，应用可同时呈现不同规则。阶段结果保留 UNKNOWN、边界和排序反转，独立留出的科学准入保持待审。

保存须用户授权，个人结果同科研记录隔离。复盘只能追加，选择以外的选项不产生观察。撤回和删除由保留最小撤销元数据的当前记录库约束；恢复有预览、校验和显式确认。导出文件由使用者保管。
