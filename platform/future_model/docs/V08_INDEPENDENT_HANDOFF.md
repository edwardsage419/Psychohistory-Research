# v0.8 独立验收交接

独立轨以 Draft PR 的实际 head 和当时的 main 为版本锚，验证 Git 源、锁文件、候选登记、首次运行及恢复。复用此分支的固定开发回放验证已知基线。独立轨单独保管未见原始任务、评分规则和标签，在给定相同信息、预算和披露顺序时比较 v0.7、简单可解释方法、普通 ChatGPT 与专业决策工具。开发和独立样本均按情节族聚类，预登记严重错误、最小实际差异、主要指标和缺失处理。保留拒答、必要追问数量、完成时间和弃用情况。

1. G01/G08 优先检查跨实例旧请求、并发结束和撤回、同意变化后恢复、时间跨界、历史显示及网络边界。确认用旧版本只读审查历史的兼容路径，拒绝旧备份恢复授权。单独核验外部来源许可、获取时效、来源撤回、恶意内容和网络无个人查询。
2. G02/G05 逐义务记录原文未覆盖、错归属、币种和周期、严格约束、逻辑作用域、条件链、语用指代、已知事实修订和撤回。区分候选、账本确认、完整决策与描述路由。分别统计错放行、错拒绝、保守未决、追问和真实操作负担。开发集的结果见公开对照。
3. G03/G04 首先验证来源资格、口径、参考与可计算参数的区分。独立复算 C028、Pareto、C029 与图表，对照同源重复、跨情景拼接、条件缺失、评价口径改动和预算中断。隔离方法的数学一致性、科学适用性和产品采纳分别签发。
4. G06/G07 检查跨决定资源、同义务重复支付、已付退款、不同义务同金额、预测到账与观察、跨时段期限、延期和旧记录复用。复算隔离反馈的双损失及留出，用真实观测、过期派生和撤回条件校验，保持未采取行动的结果为未观察。
5. G08/G09 在实体 Mac、实体 iPhone 分别登记 OS、构建、实际安装和离线冷启动。重点测同步、数据删除、备份、回退、可操作性、速度和资源占用。区分 PWA、客户端连接的本地引擎和手机独立引擎。开发工程回归可重放，独立留出、真实参与者和竞品比较由独立轨执行后单独签发。

后续接入优先补两个影响安全的缺口。第一是以原文关系和宿主确认建立条件、指代、作用域、时间口径和修订图的可信联合支持。第二是串联公开事实资格与原生参数失效、受控持久化续算及跨决策计划。待独立验收获得证据后，再审查隔离数学或反馈候选的准入。当前门槛沿用研发规格。
