# v0.4 个人决策工作台操作与开发指南

## 在环回环境运行

在 `platform/future_model/` 执行以下命令。需要 Python 3.12、Node 24、Git 和现有锁定依赖。

```bash
bash scripts/install.sh
bash scripts/verify.sh
bash scripts/run.sh --data /workspace/psychohistory-data serve --port 8765
```

打开 `http://127.0.0.1:8765/`，使用所选数据根内 `token` 文件中的令牌连接，选择「个人决策工作台」。服务、工作台和数据均应在受控的单用户环境中。令牌保留在本地，浏览器刷新后重新输入。安装与运行见 [启动规程](START_SKILL.md)。

1. 输入自然语言原文并开始澄清。逐项核对目标、行动、决策期限和硬约束。界面提供待确认的明确原文片段；碰到未知则询问。若确实没有硬约束或固定期限，可按提示明确确认。
2. 为量值填入单位、上下界、证据类型和来源。区分事实、个人估计、假设、合成情景和未知。各项目标可以保留自身单位；只有针对同一时间范围、确认了共同基数效用刻度和补偿含义的分数才可加权。权重的可行组合须非负且和为 1。
3. 确认理解并分析。核对每项底线及其判定，再阅读模型选择理由、比较图表、并列或反转条件和最先应核实的缺口。修改约束、权重、误差或情景，当前修订将重新计算。每种方法的结果有自己的条件；不同规则的冲突会保留。
4. 若希望保留结果，明确授权本地保存并保存当前修订。打开历史查看确认时的状态、计算版本和使用的依据。实际行动关联到特定已保存修订，并关闭该决策的事前快照。登记后续观察时区分真实观察与合成回访；其余方案一直标记为未观察。
5. 通过本地历史导出、删除单个决策或撤回保存授权。恢复入口先检查备份并返回隔离预览。可用备份需用户再确认方可恢复，恢复快照的旧派生分析标记为需重算。

当前理解层为确定性引导问询。它使用少量明确措辞（如「我该 A，还是 B？」）提供候选片段。没有启用可调用的大模型、联网证据搜索或领域自主推理。用户填写的来源与偏好由本人确认，界面中的来源标签不构成外部核验。

## API 和 CLI 契约

API 前缀为 `/api/v4/decisions`。已有科研 API 和 CLI 保持各自入口。请求须使用同源本地 Bearer 令牌，响应禁用缓存。默认 JSON 请求上限为 256 KiB，恢复上限为 32 MiB。

| 方法及路径 | 输入与输出 |
| --- | --- |
| GET `/models` | 固定版本的方法卡 |
| POST `/start` | `{question}` → 原文、版本化草稿、待确认片段和澄清问题 |
| POST `/analyze` | `{state}` → 输入摘要、可行性、模型审计、结果、缺口及轨迹 |
| GET / POST `/consent` | 查看状态或用空对象明确授权，返回当前授权代号 |
| POST `/save` | `{epoch,state}` → 后端重算并保存已确认的快照 |
| POST `/history`、`/record` | 当前授权代号；单项读取另需 `decision_id` |
| POST `/action` | 当前授权代号、决策 ID、选择、实际时间和所确认的保存修订号 |
| POST `/review` | 当前授权代号、决策 ID、观察内容、时间和 `real` 或 `synthetic` |
| POST `/export`、`/revoke`、`/delete` | 当前授权代号；单项删除另需决策 ID |
| POST `/restore` | `{epoch,backup,confirm:false}` 预览，明确 `confirm:true` 后重新校验并恢复 |

CLI 子命令 `decision models`、`decision status`、`decision grant` 直接运行。其余同名子命令读取 stdin 或 `--input` 指定的本地 JSON，字段与 API 一致，错误返回非零退出码。`decision restore --input` 可处理超出 HTTP 限制的完整恢复请求文件，文件须包含实际授权代号和导出信封。对私有输出文件设置限制权限。

```bash
printf '%s\n' '{"question":"我该留在虚构岗位甲，还是去虚构岗位乙？"}' |
  bash scripts/run.sh --data /workspace/psychohistory-data decision start
bash scripts/run.sh --data /workspace/psychohistory-data decision models
```

`DecisionState` 使用 `schema_version`、32 位十六进制 `decision_id`、保存修订号、不可覆盖的原文和理解收据。目标和阈值均有稳定 ID，方案数据按这些 ID 引用。边界和权重采用有限十进制，服务输出为规范 JSON。每个量值可声明时间范围，缺省继承决策期限。各模型执行结果保留方法身份和版本，输入摘要是规范状态 JSON 的 SHA-256。保存时不接受客户端提交的派生结果。

## 模型扩展和复算

`decision_registry.Method` 声明身份、固定版本、输入输出、单位、适用范围、假设、来源、失效条件、基线和可复算入口。代码内显式注册受信任实现。处理过程：

1. `DecisionHub.start` 默认返回引导问题。将来可给 `DecisionHub` 注入经授权的 `UnderstandingProvider`。适配器定义本地或外部处理范围、超时和错误处理，只有调用者明确指定本次 `allow_provider=True` 才发送原文。当前 API 不暴露此选项。适配器错误继续确定性澄清，返回建议始终待确认。
2. 通过已确认状态和 C028 后，`Context.state` 提供字段与来源，`Context.feasible` 只含通过筛查的方案。`validate(context)` 返回拒绝原因或空列表。`execute(context)` 返回带摘要的 JSON 映射，可带通用表格和区间图。只有规则定义的优选集合可放在 `leaders`，必须属于可行集。
3. 同一工作台能渲染新方法的摘要、表和图区间。新增方法无需变更协调器控制流程。用具体方法卡、正例、失败例、基线对照和固定版本登记；代码审查、工程准入与后续独立科研留出各自有记录。回退方法或新增同名版本时应显式调整活动版本，并保留历史快照身份。

| 能力 | 复算说明 |
| --- | --- |
| C028 | 对单调不等式比较最差和最好端点。已知失败主导合取，跨界、未知及冲突分开。 |
| 可比性、Pareto、权重 | 逐目标确认方向、单位、来源和时间范围。Pareto 使用可证实的逐目标优势。固定分数下，按效用差系数顺序分配有界权重以复算最小和最大差。 |
| C029 | 每情景取可行集最大效用减方案效用，再取该行最大后悔值。并列保留，额外给出最小效用基线和有条件的情景信息差。 |
| C030 | 排除自我比较，分别用对手下界减本方上界及对手上界减本方下界，逐情景与零、最坏情景取最大。已证实矩形才标记精确，否则为外界。 |
| C031 | 在点值矩阵和指定统一半径下复算严格区间分离的充分阈值。精确阈值和反例的必要性限于对应研究卡的合成几何。 |
| C034 | 在声明的联合条件下用成对得分区间和权重极值比较。完全共享的未截断加性偏移抵消，截断的共享偏移须计算端点和转折点。未知联合约束只允许保守外界或待定。 |

## 数据、恢复和部署范围

研究数据根和个人数据根并列。若 `--data` 为 `/workspace/psychohistory-data`，个人记录在 `/workspace/psychohistory-data-personal-v04`。个人根存有独立的 `consent.sqlite3` 与 `records.sqlite3`，在明确授权前保持不存在。当前部署假定信任本机账户与其文件系统，保护依赖私有文件权限。导出内容没有加密，须由用户自行保管。

个人导出使用带签名的 JSON 信封，`payload` 是可以独立解析的完整 JSON 字符串。保留原信封和原始字符串才可验证。恢复需同一仍有效的本地授权账本和能覆盖该账本事件检查点的备份。个人内容文件丢失但账本完整时，可恢复到该本地记录库并重新计算；账本也丢失时，应用只支持以用户自管文件人工查阅。删除、撤回及恢复拒绝不会删除用户自行复制的导出文件、磁盘快照或其他设备上的副本。撤回同时停止旧授权访问和写回，并清除应用管理的个人内容。旧科研备份不包含个人数据库，也不会恢复个人授权。

当前发布目标是单用户环回工作台。外部网络部署、多用户隔离、设备迁移、真实个人效果及独立科学准入尚未验收。查看 [v0.4 工程验收报告](../reports/V04_ACCEPTANCE.md)。
