# 心理史学项目工作流统一要求 v2.0

生效日期：2026-10-24。性质：项目 owner 授权的**研究执行与协调约束**，不是新的科研结果、事后修订的预注册协议，也不改变既有模型冻结。适用范围：本项目通过 ChatGPT 定时任务或人工会话推动的研究，以及相关 GitHub 归档。历史成果的原始验收口径仍以各自已冻结协议为准。

## 1. 唯一主线与阶段次序

1. **当前阶段**：优先完成既定全部 R 系列模型学习、机制审计、数据复现和逐项证据分级验收；持续按实际待核队列前进。
2. **下一阶段**：R 系列完成后，统一归纳、分类、比较模型及适用边界。
3. **最终研究阶段**：有条件地熔炼跨个体、群体、制度、历史四层机制，建立可解释、可计算、可反驳的原创模型，并独立预测检验。
4. **应用愿景**：探索客观证据辅助的个人动态人生决策基准线；现阶段只建设指标、方法、技术和市场储备，个人决策产品实施继续暂缓。
5. 新增领域不得使 R 主线退位，不得先行修改 R073 或 PESEN v0.1 等冻结状态，不得将跨文献关联或产品宣传当作科学验收。

## 2. 九项职能、三个定时任务

| ChatGPT 已有定时任务 | 原有核心职能及保持频率 | 新增子职能及目标节奏 | 核心产出 |
| --- | --- | --- | --- |
| 心理史学 R 系列持续研究 | R 系列数学模型、复现和正式验收，每小时触发 | A 公开实证数据搜寻与复现准备，每小时检查；B 独立方法复核与科学证据审计，每小时检查 | R 阶段报告、数据可用性登记、复算与审计记录 |
| 心理史学纯理论研究 | 原始理论、哲学争议与跨学科观点，每小时触发 | C 人生决策测量与因果方法，每日至少一项候选研究增量；D 外部环境、历史变迁与长期情景方法，每周至少一个专题 | TH 理论记录、测量候选与方法边界、历史情景专题 |
| 心理史学商业产品研究 | 竞品运行机制与产品证据，每小时触发 | E 科研协调与归档质量巡检，每日至少一次；F 隐私、伦理和自动化决策安全，每周至少一个专题 | 市场观察、只读治理审计、隐私安全候选规范 |

这是**三条实际定时任务承载九项职能**。A 至 F 是子任务，不具有独立系统调度器；每日或每周频率为执行目标，须由研究日志证明达成，资源、权限或平台限制可导致顺延并明确报告。不得声称每个子任务已有单独每小时触发的自动任务，也不得声称研究已实际完成。

## 3. 职责边界

- **R 主线**：先处理原有队列；冻结实验设计、训练/测试边界、指标和源码来源，执行实际复算并对未通过项保持开放。
- **A 数据**：优先真实人类重复博弈、可区分场次及个人历史的纵向数据，以及社会网络、制度、历史数据。核查发布者、版本/哈希、下载权限、数据字典、授权、缺失值、独立场次、对手配对与复现可行性。不下载或重新发布不允许分发的第三方材料。对 R073 的跨实验验证沿用已冻结模型与评分规则，不事后调参。
- **B 验证**：优先近期待验收的 R 证据，检查样本外预测、基线、泄漏、校准、重采样、敏感性、失败负例。方法上独立编写的复算、独立数据集复现及真正外部团队复现要分别命名；同一运行者内部检查不能宣称为外部独立验证。
- **纯理论**：系统整理原作者命题、竞争解释、假设和证据边界；理论兴趣广度不被短期商业用途限制。不得重复 R 模型拟合。
- **C 测量与决策方法**：研究身体和现实条件、精神体验、关系、财务、环境及长期选择空间的可测量性、信效度、误差、不可识别性；研究动态偏好、多目标权衡、因果推断、反事实与 N-of-1 设计。不同人生权重由未来使用者自主决定，不预设普适唯一最优人生。
- **D 环境与历史**：研究人口、技术、制度、宏观经济、冲突、社会结构和历史冲击的竞争机制、时间尺度、情景假设与预测外推风险。不得把历史类比直接升级为确定预测。
- **商业产品**：区分厂商宣传、技术文件、独立测试与真实决策改善证据，记录用户数据、算法、反馈、隐私和商业模式。MARKET-E 等级不得与 R 系列 E1/E2/E3 混淆。
- **E 项目巡检**：主要只读核对三条研究轨的真实进度、重复工作、冻结协议、提交/CI、数据许可和费用风险，输出问题清单；不得擅自改写其他轨的研究结果或代替科研验收。
- **F 隐私安全**：研究最小采集、本地优先、明确授权与撤回、敏感数据隔离、解释及人工否决、不确定性显示、公平和可导出性。禁止连接本人健康、财务、关系等私人资料用于当前研究。

## 4. 零新增费用红线

- 唯一允许的持续性消费：**用户现有 ChatGPT 会员订阅**。在现有设备、网络等既有资源内运行。
- 可以使用公开的免费论文、开放数据、开源软件，以及经确认无需新增付费的 GitHub 免费功能。
- **不得**新增付费 API、云服务器、GPU、数据库、第三方软件或自动化订阅、论文或数据购买、付费账户、计费 CI，也不得产生一次性新增支出。
- ChatGPT 订阅额度不代表 OpenAI API 计费额度免费；严禁利用未明确确认的付费接口。
- 对 GitHub Actions、计算任务或外部服务，若无法核实运行不会增加费用，先**不触发**；改做静态审查、轻量本地可运行验证或登记阻塞。免费额度不足时暂停相关计算。
- 研究设计不得以付费服务作为必要前提。必须增加费用的候选需求只能写入待审批记录，不会自动购买或开通。

## 5. 每轮统一执行顺序

1. **只读取证**：检查仓库 `main` 最新 HEAD、现有研究索引/队列、冻结协议、最新提交、相关子任务当天或当周是否已完成。
2. **选题去重**：主线优先；识别一个或多个确实可完成的增量，不重做其他任务已验证事项。对跨领域主题引用既有结果而不重复归档。
3. **来源与证据**：优先原始研究、公开英文或其他非中文语言原始资料，不把中文语言网站作为检索来源；标明 DOI/URL、访问日期、上游版本、许可证、实际读取范围和证据层级。
4. **实际工作**：尽可能开展阅读、代码、测试、数据结构核对、独立预测检验；严格隔离先验协议、探索诊断、真正实验结果。凡因工具或资源不可得无法执行，应标记 BLOCKED / NOT_RUN / PENDING。
5. **增量归档**：每个职能使用互不冲突的目录和独立文件名，原始证据与解释报告分离。拟使用路径：`research/Rxxx/` 为 R；`research/data_scout/` 为 A；`research/validation/` 为 B；`theory/` 为纯理论；`research/decision_methods/` 为 C；`research/historical_scenarios/` 为 D；`research/market/` 为商业；`research/operations/` 为 E；`research/privacy_safety/` 为 F。新目录均为**建议路径**，实际写入前需核对是否已有约定目录，优先沿用现有目录结构。
6. **提交防冲突**：写入前重新读取最新 HEAD 及目标文件 blob SHA；发现并发变更则重新核对或停止写入，禁止覆盖或强制推送。权限不足明确记为未同步；仅在可证实时报告 commit SHA、Git blob、CI run ID 与 conclusion。
7. **回读核验**：从远端核对提交后文件、提交身份与分支；CI 仅在已确认免费及必要时运行。提交成功不代表科研结题，CI 通过不证明模型预测有效。
8. **执行日志**：每轮报告实际完成增量、来源、证据分级、归档与 CI 状态、费用检查、下轮队列，及每日/每周子任务的完成日期。避免无变化时制造“更新”。

## 6. 成果状态与验收边界

统一报告 `COMPLETE`、`PARTIAL`、`BLOCKED`、`NOT_RUN`，分别用于已实做且核验、部分实做、有明确外部阻塞、未执行。R 系列的科研证据等级按照原冻结协议，谨慎区分合成 E1、真人行为 E2、历史类 E3；跨环境复现、样本外效果、外部独立性必须给出来源才能声称成立。

每份新记录最小字段：`track`、`subflow`、`run_date`、`observed_head`、`source_links`、`work_performed`、`evidence_scope`、`status`、`output_paths`、`commit_sha`（若有）、`ci_status`（若运行）、`billing_checked`、`blockers`、`next_action`。不适用字段写明 N/A，不编造。

## 7. 权限及后续变更

本文件是研究运作要求，继承 `docs/RESEARCH_SYNC_WORKFLOW_2026-10-15.md` 的 GitHub 同步、安全与来源纪律；不会替代已冻结的 R 系列预注册协议。修改任务频率、增加额外付费、将某个候选模型提升为既定研究基准、启用个人敏感数据或正式开展产品部署，均需要项目 owner 另行明确授权。未来更新本规范应保存版本和变更说明，不静默覆盖历史。
