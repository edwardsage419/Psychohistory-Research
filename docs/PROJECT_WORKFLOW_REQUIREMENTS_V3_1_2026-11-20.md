# 心理史学项目指令与工作流规程 v3.1

生效日期：2026 年 11 月 20 日。依据项目所有者确认的长期方向，统一供 ChatGPT 项目、Codex 及五个现有研究工作流遵循。正式仓库为 edwardsage419/Psychohistory-Research，主分支为 main。本版在 v3.0 上明确智能决策中枢的核心地位；v3.0 和此前科研记录保留历史身份。两版冲突时，项目方向以本版为准，旧科研冻结协议和证据验收标准继续有效。本次授权仅更新项目指令，不构成 Codex 版本开发、合并 PR、部署或调整工作流频率的授权。

## 一、最终目标

建立供使用者长期使用、持续研究和验证改进的通用个人智能决策系统。使用者能够用自然语言描述任何实际选择，包括身体与现实条件、精神体验、关系、职业、学习、财务及外部环境。系统主动理解问题，识别目标、底线、候选行动、时限、相关事实及未知，寻找适合的证据、数据和可解释模型，组织计算与比较，用交互图表展示取舍，在证据允许时给出有依据的建议，并支持事后复盘。

核心是可扩展的智能决策中枢，连接科研与计算模型库、数据及证据来源和个人决策工作台。用户无需自己知道应选什么数学模型，也无需先手工填满复杂表格。智能层按需追问最少必要问题，所有结构化理解、价值偏好、重要假设和最终选择由用户核对或确认。任何领域均可作为问题入口，实际分析深度须受已有数据、方法适用条件和可用算力约束；不能保证每件事都存在唯一最优解。

## 二、智能中枢与产品架构

1. 智能协调：理解自然语言问题，区分事实、用户估计、模型假设、未知和价值判断，主动澄清目标、硬约束、可选行动、时间范围及信息缺口。根据问题选择、组合或比较合适方法；记录为何选择、拒绝或暂不调用某方法，遇到模型冲突展示竞争解释与适用边界。不可因模型数量增加就机械平均结果。
2. 模型与证据枢纽：方法应可发现、可替换、可验证、可扩展。每条方法提供适用问题、版本及来源、许可、输入输出、数学或算法规则、假设、依赖、失败条件、最小复算、简单基线和证据等级。新科研成果先入候选，独立验收合格且经授权后才可上线；错误更新可回退。
3. 计算与展示：先处理不可妥协的硬约束，再按适用条件调用多目标、鲁棒性、情景比较、概率预测、信息价值、时序或其他模型。展示可行集、分歧、敏感性、关键阈值、风险与长期影响。允许用户编辑权重、假设和数据，随之重新计算与更新图表。不可比较的指标、条件未满足和未知结果均保留原义。
4. 建议与解释：在有足够证据时给出条件性建议，说明支持依据、替代方案、关键取舍、反转条件与最值得补的信息。客观观察和用户价值权重分别说明，概率必须有可追溯证据。不能将情景区间、权重空间比例、合成模拟或模型内部评分冒充真实概率、因果效果或唯一理性答案。
5. 记录与持续改进：在用户授权下保存决策当时的信息、版本、预期、选择与后来可观察的结果。区分事前与事后，未选方案保持未观察；不得用单次结果或满意度证明模型有效。新候选与当前版本及简单基线在独立留出案例上比较，记下改进、退步、适用范围、更新与回退。用户偏好更新须本人确认。

智能层应优先利用已具备的 ChatGPT 交互能力及许可范围内的免费或本地技术。现有 ChatGPT 订阅不自动等于独立应用可调用的免费大模型 API。缺少可用推理服务时，明确使用人工确认的结构化交互和确定性模型计算作为可运行降级路径，不声称已经实现自主自然语言智能体。任何外部服务接入先核实权限、成本及隐私。

## 三、执行方向与职责

个人智能决策系统是最终交付和实际优先主线。研究按决策能力缺口安排，优先解决智能协调、自然交互、模型发现与调度、可解释计算、图表比较、记录复盘、验证及隐私问题。当前工程基础为 platform/future_model/；保留 v0.1 至 v0.3 已验证功能和恢复机制，后续正式版本以用户单独授权的任务为准。不得将产品缩减为只能手动填写参数的固定公式计算器；同时不得假装尚未实现的自然语言和数据获取能力已经存在。

R 系列、跨学科理论、群体、制度及历史演化研究继续作为科学储备和未来决策方法来源。全 R 系列完成、整库分类和跨尺度模型融合均不是产品开发前置条件；已有 R 项保留各自原始科研验收与未结项。R073、PESEN v0.1、其他冻结协议、历史结果和证据等级保持原样，新验证另立记录。

ChatGPT 负责总体需求、研究问题、方法准入、证据审查、场景验收、产品方向与科研协调。Codex 在得到明确的完整版本任务授权后，负责实现、测试、工程文档与可复现交付。默认使用已设的 Codex Cloud 环境 Psychohistory-Platform，实际环境选择与状态应在任务启动时核实；仓库内 AGENTS.md 是 Codex 项目指令。此前讨论的 v0.4 草案只是建议，不因本次指令更新自动启动。方向、版本目标、开发范围、重大授权、合并、公开部署及资源约束由项目所有者决定；已确认版本内部可调整实现次序，超出范围先记录并取得授权。

## 四、五个现有工作流

保持五个小时工作流的各自触发设置与原有科研责任，按实际决策能力增量推进，避免重复研究和为提交数制造成果。每轮争取完成多个有价值步骤，遇阻转另一独立缺口。

1. 决策模型学习与接入：研究原始模型、公式、假设、反例和独立算例，优先可用于底线过滤、多目标比较、敏感性、场景、不确定性、信息价值及模型选择的规则。交付可执行方法卡、模型选择与失效条件，候选入队与正式上线分开。
2. 个人决策理论研究：从一手资料研究偏好、测量、决策过程、风险、长期反馈、因果及社会环境，将成果转为中枢追问、解释规则和反例。延续 C 每日真实增量、D 每周情景专题及理论多样性，按实际成果记录。
3. 决策真实数据与跨环境验证：核实许可、来源版本、字段、采样、时间顺序、缺失、研究与留出边界，优先能区分决策前信息、行动和后来结果的合法公开数据。交付可复核案例和局限，个人私有记录不得自动成为研究输入。
4. 个人决策产品研究与隐私：比较实际产品的开放问题输入、智能协调、模型选择、可视化、用户修订及复盘。区分宣传、实测和效果证据，形成需求与隐私验收；负责 E 日常协调与唯一近期交接清单、F 每周隐私伦理专题。保护本地存储、撤回授权、导出、删除和备份恢复。
5. 决策系统独立验收与模型更新审查：独立复算模型和图表，检查问询遗漏、错误调度、冲突条件、排序反转、用户修改响应、隐私与回退。用独立留出案例与基线比较，提出采纳或保留旧版建议；继续处理既有 R 高风险科研完整性错误，其科学结论由 R 轨保管。

## 五、证据、协作及交付

每轮读取最新 main、本规程、相关待办、近期提交、开放 PR 与协调交接清单；涉及 R 时回读实际队列、交叉索引、来源和冻结协议。使用“决策能力或缺口、来源及版本、问题、验收范围”去重。每项成果标明服务能力、源材料、阅览范围、版本身份、许可、可复算方法、结果、局限、失效条件、验收及下一责任方。

优先合法、免费、可追溯的英文或其他非中文一手资料。原论文、作者代码、真实数据与二手材料分开；理论推导、合成实验、真人实验、历史观察、独立验证和外部复现分级。严格区分归档、数学复算、程序通过、预测有效及科研结题。研究集、开发样例、独立留出与结果回访分别标明用途，避免信息泄漏与后见之明。

增量保存至原职责目录；写前核对最新 HEAD 和目标文件，避免覆盖并行成果，写后回读提交和关键文件，CI 与测试仅报告真实执行情况。待审 PR 不能写成已合并。以已完成、部分完成、待验证、受阻或未执行记录实际状态。沿用 docs/RESEARCH_SYNC_WORKFLOW_2026-10-15.md 的同步与冻结保护规则。

## 六、资源、隐私与授权

零新增费用。仅使用现有 ChatGPT 订阅、现有设备和已确认免费的开源工具、数据及 GitHub 功能。禁止未经授权增加订阅、调用计费 API、购买资料、租算力或启用费用不明的 CI；成本不明时采用免费替代或记录受阻。

公开仓库仅使用可公开的材料、匿名公共记录或虚构测试。个人决策信息、敏感记录、密钥、受限材料留在用户控制的私有环境；最小采集、明确授权、支持更正、导出、删除、撤回和恢复隔离。系统辅助理解和取舍，用户掌握价值权重、实际行动和最终决定权。
