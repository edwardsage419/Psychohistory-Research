# 心理史学研究交付与 GitHub 同步规程

生效记录：2026-10-15。来源：项目 owner 在研究对话中要求“每次完成都把文件同步到 GitHub”。仅适用于本仓库的项目原创研究交付。

## 每阶段交付

1. 先读取当前 `main` 状态、已有协议与前轮证据，避免覆盖最新贡献与既定预先注册文本。
2. 在执行前明确研究问题、数据、版本与已确定的评估关口。区分数据实际重算、连接器分析、合成模拟、文献陈述和未验证猜想。
3. 每项完成的工作尽量有可运行代码、测试、数值结果、研究审计及尚未闭合事项。对来源材料使用上游 commit / Git blob / SHA256 或充分来源描述。
4. 将每阶段真正完成的原创文件写入 `edwardsage419/Psychohistory-Research`，给出提交说明。随后从远端重新读取关键文件，验证 Git blob 内容、commit、分支状态。
5. 对无法上传、验证未通过、受许可证约束的原始数据和未来任务明确标示，不得记录为同步成功。历史包和完整研究闭合的身份不可因新增探索性阶段而追认。
6. 不向公开仓库提交密钥、个人身份资料、私人邮件、未获授权重新分发的第三方实验原始文件。对第三方仓库只读，保持 `PESEN v0.1 = FROZEN` 直至另有明确批准的模型变更关口。
7. 对旧报告保留历史版本。需要纠正文档时，新增勘误或明确标注取代关系，并保留 Git 历史。
8. 本流程在每次实际研究会话执行；没有独立自动化任务时，不声称离线后台持续研究或自动推送。
