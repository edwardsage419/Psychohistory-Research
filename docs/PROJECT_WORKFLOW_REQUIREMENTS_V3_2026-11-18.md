# 心理史学项目指令与工作流规程 v3.0

生效日期 2026 年 11 月 18 日。适用于 ChatGPT 项目会话、五个定时工作流和仓库内的项目协调。正式仓库为 `edwardsage419/Psychohistory-Research`，主要分支为 `main`。

## 一、项目目标与取舍

个人决策系统是项目主线和最终交付。使用者用自然语言说明事情，系统帮助澄清目标、底线与选项，调用适合的可解释方法，比较可能结果，用图表呈现关键取舍，在条件允许时给出有依据的建议，并支持记录、事后复盘和持续改进。

身体与现实条件、精神体验、关系、工作与学习、财务和外部环境均可成为决策背景。按问题调用文献、数据或不同模型。已有资料不足时，展示情景范围、结论成立的条件和最值得补的信息。区分事实、使用者估计、模型假设和未知，概率须有相应证据。保留使用者的价值权重、硬约束、偏好变化和最后决定权。

项目独立维护选用方法、计算、解释及处理未知的规则和模型。持续学习公开方法，从使用反馈及验证结果提出候选更新。使用留出的案例与当前版本、简单基线比较，记录改进、退步及适用范围，支持复算、版本追踪和回退。个人偏好的更新由使用者确认。记录选择与结果时，只评估可观察的结果，未选择的方案保留为未观察；不得把单次结果或满意度当作有效性证明。

## 二、执行顺序与方向管理

按个人决策系统的实际缺口安排研究。既定 R 系列、跨学科理论和群体、制度、历史研究继续积累，优先推进能支持当前能力或修复重大科研完整性问题的事项。既定 R 队列、全库分类和跨尺度模型融合无需先完成即可安排个人决策系统开发。既有 R 项仍按各自的原始科研标准验收，保存未结项和适用范围。R073、PESEN v0.1 及其他冻结协议、历史结果和证据等级保持原样；新验证另立记录。

现行依据为本规程。2026 年 10 月的项目工作流 v2.0 及 R 系列阶段顺序决定保留历史记录，其项目级优先顺序以本规程为准。方向、版本目标、阶段安排、重大授权和资源约束由项目所有者决定。任务可在已确认目标内调整研究执行顺序；偏离需先记录原因、影响与待决事项，待所有者决定。

ChatGPT 主导需求、研究问题、证据和验收；Codex 在收到独立授权的版本任务后负责实现、测试和可复现交付。本次只有规程和工作流更新。下一开发方向为个人决策工作台，正式开发任务尚未下达。近期研究可为工作台准备决策输入、可选方法、图表比较、结果回访和候选模型更新的证据与验收案例。开发入口、交付范围及启动另按用户指令执行。

## 三、五个现有工作流

五项任务沿用各自每小时触发设置。每轮优先推进多个有价值且能完成的步骤；困难事项可跨轮接续，遇单项阻塞就转另一独立缺口。以证据和决策能力增量衡量进展。

1. 决策模型学习与接入。正式学习原始模型，核对公式、假设和反例，优先满足当前决策问题的计算需求，如底线过滤、多目标比较、敏感性和在信息不足时处理范围。交付可执行的方法卡，含适用问题、输入、计算、输出、来源、失效条件、最小算例和简单基线。决定哪条方法进入候选队列与决定上线分别处理。保留既定 R 研究和原有科学验收责任。
2. 个人决策理论研究。以原始材料研究测量、动态偏好、因果推断、风险、长期反馈及相关社会环境。把证据转成具体提问、解释规则或反例，写清竞争解释和证据局限。延续理论多样性、C 每日实际增量及 D 每周情景专题的执行目标，按真实产出记录。
3. 决策真实数据与跨环境验证。深度核对公开合法案例与数据，优先能区分决策前信息、行动及后来结果的材料。核对许可、版本、实际字段、时间、缺失、采样及留出边界。交付案例、获取或复现办法、数据缺口和可复核的范围。R 外部实验资格在与当前决策或重大证据缺口相关时推进。使用者个人记录不作为自动化研究输入。
4. 个人决策产品研究与隐私。研究真实产品如何接收开放问题、展示方案、让使用者改动假设和复盘。分别记录厂商宣传、实测功能和效果证据。按需求交付产品或隐私要求；负责 E 日常协调核查和唯一的近期交接清单，F 延续每周隐私伦理专题目标。保护本地存储、撤回授权、导出删除及数据最小化，保留所有者待决项。
5. 决策系统独立验收与模型更新审查。独立复算、复查图表与建议、测试关键条件缺失或冲突、比较用户改动前后的结果、检查隐私与回退。维护与开发样例分开的留出案例，以当前版本和简单办法作基线；按结果提出采纳或保留旧版建议。继续处理既有 R 工作的高风险证据错误及有界验收，由 R 轨保有原科研结论。

## 四、共同选题、交接及证据标准

每轮先读取最新 `main`、本规程、相关待办、最近提交和开放 PR。涉及 R 时同时回读最新交叉索引、实际队列、相关源与冻结协议。使用「决策能力或缺口、来源及版本、问题、验收范围」去重，避免多人写同一文件。证据一致可引用已有复算。新增工作写明服务的决策能力、来源与版本、实际结果、局限、验收方式和下一责任方。等待正式开发时，交付研究成果和候选验收案例。

优先使用合法、免费、可追溯的英文或其他非中文第一手资料。原论文、作者代码、真实数据与二手材料分列；记录实际阅览范围、版本、许可、哈希或稳定出处。区分理论、合成实验、真人实验、历史观察、独立样本验证和外部团队独立复现。维持各研究轨证据等级的原义。归档、程序执行、数值复算、测试通过、预测有效、科研结题分别核实。开发数据、留出案例和结果回访标明各自用途，避免将后来结果当成决策时已知事实，也不因结果更改冻结条件。

按现有职责目录做增量归档。写前核对目标文件和最新 HEAD，避免覆盖并发成果，保留历史协议及收据。写后回读提交与关键文件，按实际执行报告测试与 CI。待审 PR 只算待审。无增量时可简要报告；每轮用已完成、部分完成、待验证、受阻或未执行标识结果，按实际记录日常与每周任务，禁止为触发频率或提交数制造成果。GitHub 配套规程见 [RESEARCH_SYNC_WORKFLOW_2026-10-15.md](RESEARCH_SYNC_WORKFLOW_2026-10-15.md)。

## 五、预算与隐私

零新增费用。使用已有 ChatGPT 订阅、现有设备、免费开源资源和已确认免费的 GitHub 功能。禁止未经授权调用计费 API、增加订阅、购买数据或论文、租用计算资源及启用费用不明的 CI。费用无法确认时选免费替代或记录受阻。

公开仓库和自动化任务只使用有权公开的材料、公开匿名记录或虚构例子。个人决策数据留在用户控制的私有环境，敏感记录、密钥与限制再分发的原始数据不得进入公开仓库、测试样例、共享工作流或公开日志。系统辅助理解事实和取舍，使用者保留价值判断和行动权。
